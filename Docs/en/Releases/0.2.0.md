# PocketRoot 0.2.0

[简体中文](../../../Docs/Releases/0.2.0.md) | [English](0.2.0.md) | [Documentation](../README.md)

Status: **Developer Preview candidate; no release or Git tag exists yet**.

`v0.1.0` remains the current public source and Swift Package release. This page
describes the `v0.2.0` candidate under review on `main`. It becomes an exact
resolvable version only after explicit owner authorization, a frozen release
date, and successful source-tag gates.

**Embed a local Linux Terminal and Files workspace in any iOS app.**

## Candidate capabilities

- Ready-made UIKit and SwiftUI Terminal, Files, and shared-session Workspace
  screens.
- `PocketRootIshWorkspaceHost` prepares and boots a caller-provided RootFS and
  opens those screens without business-layer readiness polling.
- Persistent SwiftTerm PTYs with input, resize, signals, EOF, ordered shutdown,
  and an iPhone keyboard row for Esc, Tab, Ctrl-C, Ctrl-D, history, and dismiss.
- Lazy inline file trees, directory navigation, bounded previews, creation,
  atomic no-replace rename, confirmed deletion, system import, and share export.
- A RootFS installer with pinned-manifest verification, private snapshots, safe
  extraction, capacity preflight, transactional promotion, reuse, rollback,
  and interrupted recovery.
- A public-Git-SHA external consumer gate covering cold Terminal/Files boot,
  foreground recovery, and shutdown.
- Continuous Xcode 16 / iOS 18 validation of RootFS, native runtime,
  iPhone/iPad UI, and public integration paths.

## Physical-device evidence

Jack iPhone (iPhone 14 Pro / iOS 26.6) completed the default 90×2-second
physical stability gate with Xcode 26.6. All 20 checks passed with one PTY open
for 90 cycles, byte-exact validation of 576 KiB of uniquely delimited zero-byte
output, one-shot command and Files cross-checks, and stdout-limit recovery.
Post-warm-up `phys_footprint` growth was 0.0 MiB and the lifecycle peak was
83.2 MiB, below the 256 MiB gate.

## Current integration version

Because the candidate is not published, production integration should continue
to pin the existing `0.1.0` release:

```swift
dependencies: [
    .package(
        url: "https://github.com/jacklv-coder/PocketRoot.git",
        exact: "0.1.0"
    )
]
```

Maintainers may validate the candidate by a complete public Git SHA during
review. Applications should not treat an unreleased branch as a stable version
constraint.

## Release boundary

The candidate prepares only PocketRoot source and Swift Package metadata. It
does not authorize or attach a RootFS, App, archive, IPA, XCFramework mirror,
or binary SDK, and it creates no tag or GitHub Release. Callers must continue to
lawfully obtain and review a local RootFS input. Runtime/App/binary distribution
and RootFS redistribution remain fail-closed.

## Still open

- Owner authorization, release date, annotated tag, and external exact-version
  resolution for the v0.2.0 source release.
- Physical iPad, real storage pressure, jetsam, and forced power loss.
- Complete RootFS NOTICE, corresponding-source delivery, and legal/distribution
  approval.
- Native Agent UI, streaming, and session persistence, paused by product scope.
